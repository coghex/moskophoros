## Findings

### GUIDE-1. Malformed PNG decoder errors escape palette validation

**Severity:** P2. **Disposition:** repair. **Verification:** verified by source
inspection and an existing repository regression fixture; not freshly executed.
**Principles:** V-2, V-11; issue #53 requirement 7, accepted D-10 and
[design §Palette inputs](https://github.com/coghex/moskophoros/blob/bb3c9b418b148deae59cbc889464fd1279a79679/docs/design.md#palette-inputs).

At [palette.py:145](https://github.com/coghex/moskophoros/blob/bb3c9b418b148deae59cbc889464fd1279a79679/src/moskophoros/palette.py#L145),
the PNG decoder boundary catches several decoder exceptions but omits
`IndexError`. A PNG with otherwise decodable pixels and a CRC-correct, empty
trailing `iCCP` profile chunk passes the chunk checksum verification; loading
then indexes the empty profile payload. The pinned dependency is Pillow 12.3.0.
Its [versioned decoder source](https://github.com/python-pillow/Pillow/blob/12.3.0/src/PIL/PngImagePlugin.py)
confirms the unchecked indexing in `chunk_iCCP`, and `load_end` does not catch
that exception. This establishes the failure path without importing or running
the dependency.

The project already generates this exact malformed-chunk fixture in
[test_capture_blender.py:536](https://github.com/coghex/moskophoros/blob/bb3c9b418b148deae59cbc889464fd1279a79679/tests/test_capture_blender.py#L536)
and [test_capture_backend.py:599](https://github.com/coghex/moskophoros/blob/bb3c9b418b148deae59cbc889464fd1279a79679/tests/test_capture_backend.py#L599).
Those tests protect the capture boundary, not the palette reader.

**Consequence:** `--palette broken.png` propagates `IndexError` past
[cli.py:255](https://github.com/coghex/moskophoros/blob/bb3c9b418b148deae59cbc889464fd1279a79679/src/moskophoros/cli.py#L255),
which catches only `PaletteError`, to the generic internal-error handler at
[cli.py:429](https://github.com/coghex/moskophoros/blob/bb3c9b418b148deae59cbc889464fd1279a79679/src/moskophoros/cli.py#L429).
It prints a traceback and returns 1 rather than the required palette-file
diagnostic and exit 2. It still fails before Blender; the defect is the error
contract, not a wrong sheet.

**Smallest action:** normalize this decoder failure to `PaletteError` and add
the existing empty-profile fixture to palette/command coverage, asserting exit 2,
the palette filename and no subprocess invocation. No correction was applied.
The #56/#59 canonical reviews, effective issue amendments and prior cursor do
not already cover this exception. Their existing notes about filename restrictions
and unsupported-suffix reads are not repeated as new findings.
