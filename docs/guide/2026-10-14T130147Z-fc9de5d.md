### [#109] GUIDE-1. Give auxiliary render scratch the command workspace's lifetime

**Disposition:** repair, medium priority. **Verification:** reproduced on the pin.
**Principle:** V-2; design §CLI and §Capture require temporary capture directories to be deleted after success or failure, with explicit retention under `--work-dir`.

**Evidence:** [src/moskophoros/capture/blender_script.py:1650](https://github.com/coghex/moskophoros/blob/fc9de5d63da34359049e0655c27f5f7778a20d21/src/moskophoros/capture/blender_script.py#L1650) creates an unrelated system temporary directory. Removal at line 1683 is reached only after every frame succeeds. `render_auxiliary` at line 1699 restores scene state in `finally`, but deletes its files afterward. [src/moskophoros/cli.py:1284](https://github.com/coghex/moskophoros/blob/fc9de5d63da34359049e0655c27f5f7778a20d21/src/moskophoros/cli.py#L1284) owns and deletes only the command workspace; [src/moskophoros/capture/blender.py:218](https://github.com/coghex/moskophoros/blob/fc9de5d63da34359049e0655c27f5f7778a20d21/src/moskophoros/capture/blender.py#L218) kills and waits for its child on interruption. A child-only `finally` cannot cover that kill path.

The real-Blender probe wraps `save_exr`, calls the original, then raises `OSError`. Using `edges(tmp_path)`, it invokes `cli.run` with `--no-user-config --directions 1 --cell 8x8 --supersample 1 --no-preview --ao-samples 1`. Exit 5 was correctly reported and the parent workspace was gone, but the sibling scratch directory still held `auxiliary.exr` (4,586 bytes) and `auxiliary.tga` (795 bytes). This is an injected failure after real file creation, not an observed spontaneous renderer failure. The interruption exposure is established by ownership and the kill path, not by a signal experiment.

**Consequence:** repeated failed or interrupted exports can accumulate render files outside the requested workspace; retained runs also leave those files somewhere the owner did not request. The EXR added by PR #102 makes the leak more costly at larger capture sizes. No final-output corruption was established.

**Action:** one narrow lifecycle repair with failure/interruption regressions, preserving successful bytes and existing retention semantics. PR #76 introduced the directory and PR #102 added the EXR; neither canonical review nor the open backlog already owns this repair. The probe patch and output are preserved in local evidence as `probe-scratch.patch` and `probe-scratch.log`. Apply the patch to a checkout of the pin and run `.venv/bin/pytest tests/blender/test_guide_scratch.py -q -s`; its passing assertion detects the defect.

Title: **Clean auxiliary render scratch after failures and interruption**

Label: `bug`. Filed exact body:

```markdown
## Background

Auxiliary capture scratch is outside the command-owned workspace. At `fc9de5d`, `capture/blender_script.py:1650` creates a system temporary directory; line 1683 removes it only after the entire render succeeds. `render_auxiliary` restores scene state in a `finally`, but file deletion happens later. An exception or an interrupted Blender process can leave TGA/EXR files behind, even when the command deletes its own workspace.

A guide probe using a generated GLB and real headless Blender injected an OSError immediately after `save_exr`. The command returned exit 5 and removed its temporary workspace, but a separate auxiliary directory retained a 4,586-byte EXR and 795-byte TGA at an 8×8 cell. Larger captures leave larger files. Design §CLI and §Capture promise temporary workspace cleanup on failure; retained artifacts belong under an explicit `--work-dir`.

## Requirements

1. Auxiliary scratch has command-owned lifetime. Successful runs remove intermediate TGA/EXR files. Failed runs and command interruption leave no auxiliary scratch outside the capture workspace.
2. Without `--work-dir`, the command removes auxiliary scratch on failure and interruption. With `--work-dir`, any retained failure artifacts stay inside that directory, following its existing retention contract.
3. Keep successful capture/output bytes, exit classifications, scene restoration and final-output rollback unchanged. Interrupt only the Blender process started by this command.
4. Add regression coverage for success, an exception after intermediate files exist, and command interruption, including the retained-workspace case. Use generated models, temporary directories and explicit process coordination, never sleeps. Blender-dependent tests stay in `tests/blender/` with the registered marker.

## Acceptance

- `.venv/bin/ruff check .` and `.venv/bin/ruff format --check .` pass.
- `.venv/bin/pytest -m "not blender"` and `.venv/bin/pytest -m blender` pass without skips; the new tests observe filesystem cleanup/retention and unchanged earlier final outputs on failure.
- Run `.venv/bin/python tools/validation/plan.py --base origin/master --head HEAD`, complete its selected groups and include the required current-commit `local-validation` block in the pull request.

## Out of scope

Changing rendering, shading, buffer encodings, defaults, retention/replay interfaces, or deleting pre-existing orphan directories from earlier runs.

## Related

- Guide: `docs/guide/2026-10-14T130147Z-fc9de5d.md`, GUIDE-1.
- #66 / PR #76 introduced the scratch directory; #96 / PR #102 added EXR intermediates.
- `docs/design.md` §CLI and §Capture job and result contract; vision V-2.
```
