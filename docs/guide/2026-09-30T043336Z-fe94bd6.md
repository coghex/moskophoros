# Guide review: the CI foundation (issues #4 to #7)

The four merged pull requests that built the CI foundation (#8 to #11) are
aligned with the vision and meet their issues as written. The harness, catalog,
planner, image and aggregate `build-test` all work at the pin, and every check
passed. The review found seven gaps a per-PR review could not see. The most
urgent is GUIDE-1: the next pull request that touches the package has no honest
way to satisfy its Blender obligation. The others are a stale-check window,
unpinned image identity, a check-name collision, a build-context leak, test
gaps and two doc errors. This covers `origin/master` at
[`fe94bd6`](https://github.com/coghex/moskophoros/commit/fe94bd6995a3f370b7b8d222ce8d7839e76225da),
from boundary `0eb2491`. It is not a whole-project correctness claim or an
approval.

## Findings

### [#12] GUIDE-1. Decide how `test.blender` can be honestly satisfied before Blender tests exist

**Disposition:** owner decision.
**Verification:** verified.
**Principle:** V-12; CI foundation design D-7, D-20, D-21; `AGENTS.md` "A skipped test is not a passing test".
**Evidence:** `test.blender` runs `pytest -m blender`, which collects nothing today (exit 5), as [`docs/validation.md:69-71`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/docs/validation.md#L69-L71) admits. It is affected by `src/`, `pyproject.toml` and `requirements.lock`, and only a `passed` report satisfies it. Running the planner on PR #8's own range (`--base 0eb2491 --head 6140340`) gives `test.blender … FAILED: no local-validation entry reports it`, exit 1.
**Consequence:** slice 1's first pull request, and even a dependency-only lock bump, fails `build-test` unless it reports `passed` for a run that tested nothing. The docs never say what to report.
**Action:** choose one:
- add a real Blender smoke test under `tests/blender/` now, for example one that checks the installed Blender is the supported 5.2 series, so the group is never empty;
- accept an explicit "no tests yet" outcome only while the group collects zero tests;
- narrow `test.blender`'s paths until Blender tests exist.

The first matches the design's intent best.

### [#14] GUIDE-2. Close the window where a body edit leaves the previous `build-test` pass standing

**Disposition:** repair.
**Verification:** verified.
**Principle:** V-12; D-16 ("the run the edit started decides").
**Evidence:** [`ci.yml:10-14`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/.github/workflows/ci.yml#L10-L14) replans on `edited`, but `build-test` ([`ci.yml:130-132`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/.github/workflows/ci.yml#L130-L132)) only gets its check run when the job starts, after planning and the groups. On PR #11's head `29fe3f7`, the body-edit run was created at 04:22:12, but its `build-test` check only started at 04:24:47. Until then the newest `build-test` was the previous pass (04:21:48). The review gate does not rerun on `edited`.
**Consequence:** for a couple of minutes after an author adds a request, or changes a report to `failed`, an approved pull request still shows a green `build-test` planned from the old body. `/finalize` or the drainer, which treats the newest check as authoritative, can merge in that window.
**Action:** make a fresh `build-test` exist as soon as the run starts, for example a `build-test` job that starts immediately and waits for the others. Alternatively, have merges wait until no CI run for the head is still in progress. Either way, the choice needs the owner, since the first costs runner time and the second touches Kanban.

### [#15] GUIDE-3. Check the descriptor's digest and versions, not only its fingerprint

**Disposition:** repair.
**Verification:** verified (probe).
**Principle:** V-2; D-14 ("CI runs exactly the descriptor's digest"); CIF-4 scope ("the check that the descriptor matches the candidate").
**Evidence:** [`ci.py:133-154`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/tools/validation/ci.py#L133-L154) relies on `check_descriptor`, which compares only `recipe_fingerprint` ([`image.py:266-274`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/tools/ci-image/image.py#L266-L274)). The probe changed the descriptor's digest to all zeros and its ruff version to `0.1.0`; `ci.py plan` still exited 0 and reported the descriptor current. `ci-image.yml` deliberately skips descriptor-only pull requests, and PR #10's `check-image` command, which inspects the image's labels, is never called from CI.
**Consequence:** a descriptor naming a stale or wrong digest passes every required check, and CI then runs tools other than the locked ones.
**Action:** have planning also confirm that the named image's labels match the descriptor's fingerprint and versions, reusing `check-image`. Issue #7 as written asked only for the fingerprint, so this is new scope.

### [#16] GUIDE-4. Stop catalog group IDs from creating checks with required names

**Disposition:** repair.
**Verification:** verified (traced).
**Principle:** the review gate's contract; issue #7 requirement 4 ("the only job with that name").
**Evidence:** group jobs are named `${{ matrix.group }}` ([`ci.yml:83`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/.github/workflows/ci.yml#L83)), and the ID pattern ([`plan.py:25`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/tools/validation/plan.py#L25)) accepts `build-test` and `review-approved`.
**Consequence:** a pull request adding a floor group named `review-approved` with command `true` publishes a passing `review-approved` check that the ruleset and the drainer cannot tell from the review gate's. A same-repository author could already edit the workflows, but this path hides in a data file a reviewer may skim.
**Action:** prefix group job names (for example `group check.static`), or have the catalog check reserve the required names.

### [#17] GUIDE-5. Keep `.gitattributes` from changing the image build context unfingerprinted

**Disposition:** repair.
**Verification:** verified (probe).
**Principle:** V-2; D-14; issue #6 requirement 2 ("only files the fingerprint covers can reach the build").
**Evidence:** `stage` builds the context with `git archive` ([`image.py:191`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/tools/ci-image/image.py#L191)), which applies `.gitattributes` (`export-ignore`, `export-subst`, line-ending conversion). `.gitattributes` is not a fingerprint input. The probe added only a `.gitattributes`: the fingerprint stayed the same while a staged file vanished and another had its contents rewritten. [`docs/validation.md:338`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/docs/validation.md#L338) says "nothing else can reach the build".
**Consequence:** latent today, since the repository has no `.gitattributes`. The first one added could publish a different image under an existing fingerprint.
**Action:** write each fingerprinted blob out directly (for example with `git cat-file`) instead of using `git archive`, or add `.gitattributes` to the fingerprint inputs. Add a regression test.

### [#18] GUIDE-6. Pin the planner's three-dot comparison and text reasons in tests, and fix its non-UTF-8 crash

**Disposition:** repair.
**Verification:** verified (mutation and path probes).
**Principle:** V-12; D-13; issue #5 requirements 5, 11 and 12.
**Evidence:**
- The test fixture ([`test_plan.py:76-90`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/tools/validation/test_plan.py#L76-L90)) never advances `master` after branching. So changing [`plan.py:350`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/tools/validation/plan.py#L350) to a two-dot comparison leaves all 78 planner tests passing.
- The text-versus-JSON test ([`test_plan.py:714`](https://github.com/coghex/moskophoros/blob/fe94bd6995a3f370b7b8d222ce8d7839e76225da/tools/validation/test_plan.py#L714)) compares the planner with its own `describe()`. Dropping the named paths from "affected by …" also survives.
- Separately, text mode crashes with `UnicodeEncodeError` on a non-UTF-8 path and exits 1, which means "obligation failed". CI uses `--json`, so CI is unaffected.

**Consequence:** a regression in D-13's comparison or in the promised explanations would merge silently. The text mode's exit-code contract is broken for one input class.
**Action:** advance `master` in a fixture so the merge base differs from the base, assert the text form's reasons independently, and print paths safely in text mode.
