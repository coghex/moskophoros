# Shading pre-arc baseline and SHD-2 byte identity

Evidence for the shading arc (epic #137, [shading design](../designs/shading_design.md)
§Verification strategy, *Compatibility*). It is a record of what was run, not a
design: the design owns the contract. Generated sheets, previews and models
stay outside the repository, in local evidence (below).

## The pinned baseline

- **Manifest name:** `shading-pre-arc`, a name and not a Git tag.
- **Source:** commit `f548312a5a929fb9bd843855b83b9762123f80ab`, an ancestor of
  `master` at `1f2aac349c7022b863264416b533c37da1f456d9`. Between the two,
  `git diff --stat` over `src`, `tests`, `tools`, `pyproject.toml` and
  `requirements.lock` is empty: the fourteen commits are documentation only.
- **Clean copy:** `git archive f548312a… | tar -x`, never a reset worktree, with its own
  virtual environment installed from that copy's `requirements.lock`
  (sha256 `86f3d9a7b64c1882b5825bc3b8157dcc3d37d4d6eb04731659391520e1a3de43`).
- **Tools:** macOS 26.7.1 (arm64), Python 3.14.8, numpy 2.5.3, Pillow 12.3.0,
  PyYAML 6.0.3, Blender 5.2.2 LTS (build date 2026-09-15) at
  `/opt/homebrew/bin/blender`, run headless as `-b --factory-startup -noaudio`
  by the tool, under `~/.local/state/project-manager/moskophoros/blender.lock`.
  The pinned copy and the SHD-2 worktree have the same installed packages.
- **Configuration:** every run had an empty `HOME` and `XDG_CONFIG_HOME` of its own and
  `--no-user-config` (or `--config` where the case names a file); no owner file was read.

## SHD-2 against the baseline

The same twenty-four commands run with the pinned copy and with SHD-2's head
`58a610813397af297cfbc7dc793b62a29d2fa9b2`. **All 103 files per side are
byte-identical, sheet JSON included; there is no allowed difference.** Every run
exited 0. The set covers plain and mode reduction, hard and soft edges, ordinary
materials, a palette without a library, `/2` and `/3` libraries with generated
ramps, per-material and library-wide shade values, options and a `--config`
giving shade values, the normal and depth maps, lit previews and a perspective
camera with roll.

## SHD-4 against the baseline

SHD-4 (#141) adds the pure `dither` module (the six threshold tiles, the
dithered band coordinate and the two-nearest snap) and gives
`lighting.shade_blocks` an optional pattern, strength and output-cell
coordinates; with none given, or `off`, or strength 0, it takes the path it took
before. It wires nothing into a command. The same twenty-four commands, with the
pinned copy's recorded hashes and with SHD-4's head
`b0ec41f6e6fca373e1e02cd7fc29f7721463a308`: **all 103 files per side are
byte-identical, sheet JSON included; there is no allowed difference.** Every run
exited 0. The inputs are the ones above, with the same sha256.

## SHD-5 against the baseline

SHD-5 (#142) adds `shade_layers` and gives `stylize.plain` and `stylize.mode`
the keyword-only arguments `shading` and `lights`. It wires nothing into the
command: `cli.py` is unchanged and passes neither argument, so the public
default command is exactly as before. The same twenty-four commands, run with
the pinned copy's recorded hashes, with a clean `git archive` copy of master
`0ae27fa` (its own virtual environment from that copy's `requirements.lock`,
sha256 `86f3d9a7…`) and with SHD-5's head
`98b8f2fd8bbc293762933495aebb25a86ebf064f`: **all 103 files per side are
byte-identical across the three, sheet JSON included; there is no allowed
difference.** Every run exited 0. The inputs are the ones above, with the same
sha256. The new path itself is covered by stage tests, not by this matrix,
since no public option reaches it: with the default response and a library it
equals the historical reduction on random layered and opaque frames, both
reductions and both edge rules.

## SHD-6 against the baseline

SHD-6 (#143) activates the shading controls, `moskophoros.sheet/15` and
`moskophoros.materials/4`, and the command now passes the resolved shading to
stylize on every run. The same twenty-four commands, plus four more, were run
with a clean `git archive` copy of master `29e66f666295a19cd463a423976992be4fae8499`
(its own virtual environment from that copy's `requirements.lock`, sha256
`86f3d9a7…`; master differs from the `4e03ad0` of SHD-5 by documentation only)
and with SHD-6's head `2378e78645c9e1ddf221e22f8474b3293412f0b2`, and compared
with the pinned baseline's recorded hashes. Every run exited 0.

**Image and preview bytes.** All 171 non-JSON files across the 24 cases and
the 4 extra cases are byte-identical to the baseline: sheets, normal and depth
maps, flat and lit previews; plain and mode reduction; hard and soft edges;
ordinary materials; a palette without a library; `/2` and `/3` libraries with
generated ramps, per-material and library-wide shade values, options and a
`--config` file giving shade values; a perspective camera with roll. Master's
own outputs, sheet JSON included, equal the baseline's. The four extra cases
(`props-lib4-plain-hard`, `props-lib4-mode-soft`, `props-lib3-explicit-defaults`
and `hero-explicit-defaults`) have images equal to the corresponding baseline
cases: a `/4` library that says what `lib3.yaml` says (its `plain: ordinary`
written `{ordinary: true}`), and the default command given every new shading
option at its default value. **No image difference is accepted or listed.**

**Expected JSON changes, listed separately.** In each of the 24 `sheet.json`
files, `compare6.py` found exactly these differences from the baseline's, and
no others:

- `schema` is `moskophoros.sheet/15`, was `/14`;
- `settings.shade` gains, after its five existing members and in this order,
  `mode: "ramp"`, `ambient_form: true`, `key: {direction: [-0.5183210553488161,
  0.604707897906952, 0.604707897906952], strength: 0.0}`, `sky: {strength:
  0.0}`, `ground: {strength: 0.0}`, `sky_ground_frame: "camera"`,
  `brightness: {floor: 0.3, ceiling: 1.0}`, `snap: "off"` and `dither:
  {pattern: "off", strength: 1.0}`;
- `fingerprint` changes with them. Both fingerprints were recomputed from their
  own sheet's canonical JSON and match, the baseline's and head's alike.

The inline library record of every case is unchanged, so a `/2` or `/3`
library records exactly as before.
